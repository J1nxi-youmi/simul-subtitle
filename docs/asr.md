# 语音识别（ASR）

## 当前内置模型

同传字幕内置 **ReazonSpeech k2 v2 ja-en** 离线模型，采用 `sherpa-onnx` 的 int8 量化导出版（[csukuangfj/reazonspeech-k2-v2-ja-en](https://huggingface.co/csukuangfj/reazonspeech-k2-v2-ja-en)，原始模型由 [ReazonSpeech](https://github.com/reazon-research/ReazonSpeech) 发布），由单个模型同时覆盖**日语**和**英语**识别。

### 关键实现细节

- **体积与打包方式**：模型总计约 **77 MB**（`encoder` 70.9 MB + `decoder` 5.2 MB + `joiner` 1.0 MB + `tokens`），连同 **Silero VAD**（0.6 MB）直接随应用打包分发：
  - **Android**：存放在 APK 的 `assets/models/` 下，构建时设置 `.onnx` 不压缩，由 `sherpa-onnx` 直接读取，无需首次启动解压。
  - **桌面端（Windows）**：存放在应用自带资源目录的 `models/` 下。
- **首尾静音填充**：送入识别前，音频前后各补 **0.3 s 静音**——实测若有效语音从第 0 个采样点直接开始，该模型容易吞掉句首第一个词。
- **双语混识与语言选择**：该模型本身没有“指定识别语言”的参数，也不输出语种标签。用户在首页选择的「视频里说的是（日语 / 英语）」不改变底层声学识别，而是用于告知后续的翻译提示词与 Jev 判断当前原文语种。
- **已知局限**：在听日语节目时，偶有短片段被模型当作发音相近的英语单词输出。

## 与 SenseVoice-Small 的实测对比

### 测试基准

- **硬件与环境**：Mac M4 Pro，2 线程，int8 量化，`sherpa-onnx` 1.13.8。
- **解码方式**：整句离线解码，音频首尾各补 0.3 s 静音。
- **数据集**：FLEURS 朗读语音测试集（日语 650 句、英语 647 句；注：朗读语料与真实直播口语存在差异）。
- **评测口径**：日语计算字错误率 **CER**（NFKC 归一化，去除标点与空格）；英语计算词错误率 **WER**（转小写，去除标点）。

### 对比结果

| 指标 | ReazonSpeech k2 v2 ja-en（现用） | SenseVoice-Small (2024-07-17) |
|---|---|---|
| **日语 CER** | **8.48%** | 7.52% |
| **英语 WER** | 22.66% | **8.33%** |
| **语种标签输出** | 无 | 有（ja 649/650，en 647/647） |
| **文本输出形态** | 日语无标点；英语全大写、无标点、数字拼写为单词 | 自带标点、大小写与阿拉伯数字 |
| **实时率（RTF，解码耗时 / 音频时长）** | **0.0075** | 0.0164（慢约 2.2 倍） |
| **单句解码中位数（日 / 英）** | **93 ms / 71 ms** | 203 ms / 157 ms |
| **模型文件体积** | **77 MB** | 239 MB |
| **加载后进程内存增量（桌面端）** | **约 +214 MiB** | 约 +837 ~ 973 MiB |

### 评估说明与选型结论

1. **指标说明**：错误率基于上述自定义文本归一化脚本计算，不可与公开论文榜单直接横向对比；耗时仅统计 `decode_stream()` 在 Mac 上的表现。
2. **语言强制参数无效**：实测将 SenseVoice 的参数设为 `language="ja"` 时，夹杂的英语片段仍会被识别为英语，无法靠该参数规避跨语种误识。
3. **直播场景抽查**：在真实直播录音切片上对比，两款模型在短促口语片段上的输出分歧较大，因无标准参考文本，难以单凭朗读集断言谁在直播场景下绝对占优。

**当前选型结论**：继续采用 **ReazonSpeech**。它在日语上的准确率与 SenseVoice 差距很小，但**解码速度快一倍以上、安装包体积仅 1/3、内存占用不到 1/4**，更适合手机后台与桌面常驻同传；英语识别准确率较低属于当前权衡下的已知取舍。

## 与纯日语模型的实测对比

纯日语模型 [reazonspeech-k2-v2](https://huggingface.co/reazon-research/reazonspeech-k2-v2)（sherpa-onnx 导出版 `sherpa-onnx-zipformer-ja-reazonspeech-2024-08-01`）曾被列为「消除日语被误识为英语」的候选，2026-10 实测后**不切换**：

| 指标 | ReazonSpeech k2 v2 ja-en（现用） | reazonspeech-k2-v2 纯日语 |
|---|---|---|
| **FLEURS 日语 CER**（口径同上，650 句） | 8.57% | 8.56% |
| **实时率（RTF，Mac M4 Pro，2 线程）** | **0.0080** | 0.0107（慢约 34%） |
| **模型文件体积**（int8 encoder + decoder + int8 joiner） | **77 MB** | 169 MB |
| **15 分钟真实直播：含英文字母的识别结果**（VAD 切出 141 段） | 1 段 | 0 段 |

- 现用模型在 FLEURS 上复测为 8.57%，与上文 8.48% 接近（相差 0.09 个百分点，可能来自 `sherpa-onnx` 版本或归一化细节），两次测量口径可以对比。
- 真实直播中「日语被识别成英语」只有 1 段（「スパチャすら」→「スーパーJUST」），问题本身很少出现；纯日语模型在朗读集上同样会输出英文字母（原文里的缩写）。
- 两个模型在直播片段上的 141 段里有 92 段输出不同，抽查 25 段互有优劣：纯日语模型有段落更准，也有整段只剩一个字、把「弾幕」识别成「段膜」的情况。
- `sherpa-onnx` 发布的 `sherpa-onnx-zipformer-ja-en-reazonspeech-2025-01-17` 与现用模型的文件逐字节相同，并非新版本。

结论：准确率相同，体积翻倍、速度更慢，而要解决的问题在直播中极少出现，继续使用现用模型。
