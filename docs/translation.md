# 翻译

翻译用你自己填的 OpenAI 兼容服务（BYOK）：服务地址、模型 ID 和 API Key 都由你提供，费用由服务商按你的用量收取。App 不再内置免费的在线翻译，也不能在手机上本地运行翻译模型（0.6.5 是最后一个带这两种方式的版本）。

只发送识别出的文字和提示词，不发送声音。

## 对模型的要求

- **必须能关闭思考**（深度思考 / reasoning）：字幕每句都要实时翻译，思考会让每句都等很久。App 会自己试出关闭思考的参数（见下文）。
- **尽量选回复速度快的模型**：发出后 5 秒内没收到译文，这句判为失败；收到后整句最多等到发出后 8 秒。模型越快，字幕越跟得上。

请求用流式（`stream: true`）；字幕整句显示；断网或失败时这句显示「翻译失败」；不重试。

## 协议与关闭思考

- 协议：OpenAI 兼容的 `POST {地址}/v1/chat/completions`，`Authorization: Bearer {key}`。地址结尾有没有 `/v1` 都可以；只接受 `https://`，不带用户名、`?` 参数和 `#`；不跟随重定向，免得把 key 发到别的地方。
- **关闭思考**：没有统一的参数。第一次使用某个「地址 + 模型」时（点「测试连接」或第一次开始字幕），用一句固定的日语依次尝试下面的参数，第一种**正常结束、有译文、且没检测到思考内容**的就记下来，以后都用它。这只说明那次回复里没看到思考，不能证明服务真的执行了关闭（服务可能忽略参数、把思考藏起来）。最多尝试 6 次、每次最多 8 秒，每次都是一次计费请求：
  1. `thinking: {type: disabled}`（DeepSeek 等）
  2. `chat_template_kwargs: {enable_thinking: false, thinking: false}`（vLLM / SGLang 部署的 Qwen3、DeepSeek 等）
  3. `enable_thinking: false`（SiliconFlow、阿里云百炼等）
  4. `reasoning: {enabled: false}`（OpenRouter）
  5. `reasoning_effort: none`（OpenAI 推理模型、Gemini 的 OpenAI 兼容接口）
  6. 不加参数（本来就不思考的模型）

  判断「有思考」：回复里有 `reasoning_content` / `reasoning`、`<think>`，或 `usage.completion_tokens_details.reasoning_tokens > 0`。参数不被接受（例如 HTTP 400）就试下一种；key 错（401/403）、地址或模型错（404）、限流（429）、连不上时直接停止。全部失败才提示「关不掉思考，可能很慢」，但仍允许使用。思考内容不会显示成字幕。
- 测试时每种参数最多等 8 秒，不受首字限制；正式翻译仍是首字 5 秒 / 总共 8 秒。中途遇到超时、5xx 等不确定的结果时不记结论，下次再试。
- 服务的回复原文（流式内容、思考内容、错误回复，都可能夹带 key）一律不写进使用记录，只记去掉思考和 key 后的译文、HTTP 状态、计时和 usage。
- key 在手机上用 Android Keystore 加密保存，在 Mac 上存在钥匙串里；都不写进使用记录；译文里如果出现 key 会被删掉。

## 提示词

按前缀缓存排序（见下节）：

- `system`：翻译要求、原文/译文语言、场景背景、**整份**术语表（只在译成中文时给），同一套设置下每句都相同（运行中改了场景或语言，才换一份新的）；
- `user`：`【前文】`（如果开启，最近说完的几句原文，只用于理解指代和省略）→ `【当前句】` → `【注意】`（Jev 检查出问题后重译时附带的修正提示，见 [jev.md](jev.md)）。
- 原文语言选「不确定」时，提示词里写「外语」，由模型自己判断。
- `temperature: 0`；一句输出上限：中文 160 token，其他语言 256 token。

## 前缀缓存

服务端的前缀缓存只复用模型输入里**从开头起完全相同**的那段 token；有没有缓存、最短多长才缓存、按多大粒度缓存，各家不同且会变（以服务商自己的文档为准），有的服务根本没有。

| | 能复用的前缀 | 原因 |
|---|---|---|
| 不同句子 | 整个 `system`（要求 + 背景 + 整份术语表） | 固定内容全放 `system`，变化的前文和当前句放最后 |
| 同一句的草稿 → 定稿 → 重译 | App 自己复用：提示词完全相同时直接用上次的译文，不再请求 | 与服务端缓存无关 |

- 前文是滑动的（每句都会变），所以 `user` 部分基本不能跨句复用；为了缓存无限累积对话没有意义，也会变慢。
- 这里只保证**请求的排列适合前缀复用**；`system` 有多少 token、能不能达到某家的缓存门槛、实际命中多少、快多少，都没有测过。不会为了凑门槛填充文字。
- 使用记录的 `mt` 事件记录服务回报的 `cached_tokens`（`prompt_tokens_details.cached_tokens` 或 DeepSeek 的 `prompt_cache_hit_tokens`），没有回报就是 `null`，不代表没命中。

## 结合上文

设置里的「结合上文来翻译」默认开启、参考 2 句，可以调成 1–5 句或关闭；字幕运行中改了，从下一句开始生效。

- 上下文是最近几句**非空定稿**的原文。
- 一个段落的上下文在它前一句定稿翻译完后固定下来，所以同一段的草稿、定稿和重译用的是同一份提示词，复用缓存继续有效。
- 句数越多，每次翻译要处理的文字越多，速度越慢。

## 场景

| 场景 | 背景说明 | 术语表 |
|---|---|---|
| 通用 | 无 | 无 |
| B站 VTuber 直播 | B 站直播闲聊、念弹幕和 SC、原文是语音识别结果 | ビリビリ→B站、スパチャ→SC、配信→直播 等 |

## 支持的语言

- **原文**：日语、英语、不确定（日语或英语）。受语音识别模型限制。
- **译文**：22 种语言：中文、英语、日语、韩语、德语、法语、西班牙语、葡萄牙语、俄语、阿拉伯语、意大利语、荷兰语、波兰语、罗马尼亚语、瑞典语、土耳其语、印地语、越南语、泰语、印尼语、马来语、菲律宾语。
- 日译中以外的语言对没有专门调过提示词和输出长度。
